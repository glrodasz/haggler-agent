# Targets for "haggler probe --mode bundles" (.github/workflows/probe.yml, mode=bundles): can our
# fetcher read the official pages of the promotional bundles? The readability matrix it prints
# decides each bundle's watch mode (only "readable" pages may be "auto") and the watcher's
# anchors are copied from its quoted lines.
#
# Format: one target per line
#     <label> <CC> <url>
#   label  a bundle_id from data/curated/bundles.yaml, or a free snake_case label for a page that
#          is not in that file yet (terms page, price list index, a new country's offer ...)
#   CC     ISO 3166-1 alpha-2 code from catalog/countries.yaml: the country whose site and
#          currency the page must show (for a known bundle_id, the bundle's own country)
#   url    https:// on a public host
# Lines starting with "#" and blank lines are ignored; "#" after a space starts a comment.
#
# Override for a single manual run: Actions > probe > Run workflow > mode "bundles" > "targets",
# separated by ";" (e.g. "meli_plus_co_total CO https://...; apple_one_co CO https://...").
# The workflow turns every ";" into a line break, so URLs containing ";" go in this file.
#
# Every target is one real request to the vendor (robots.txt is checked on every hop, 1 request
# per 3 s per host). Walls, robots.txt and login pages are reported, never worked around.

# URLs below come from web searches on the providers' official domains (2026-10-09); none had been
# fetched before this probe. Pages that price by visitor IP will show the runner's (US) prices:
# the probe reports them as wrong_country, which is the finding.
